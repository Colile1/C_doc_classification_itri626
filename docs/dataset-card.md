## Classes used

Eight of the sixteen. The reason for including each is given in the table.

| Class | Description | Why included |
|-------|-------------|--------------|
| invoice | Itemised billing documents, tabular line items and totals | Common financial attachment; visually close to budget |
| budget | Dense numeric tables and financial summaries | The statement-like financial class; main confusion partner for invoice |
| form | Printed documents with labelled fields and ruled boxes | Completed application and verification forms |
| letter | Formal correspondence, header block and body paragraphs | Proof of address and confirmation letters |
| memo | Short internal correspondence with a structured header | Visually close to letter; tests fine layout discrimination |
| handwritten | Pages consisting mainly of handwriting | The low-quality submissions that most often need human review |
| resume | Curriculum vitae pages with sectioned headings | Employment verification; distinctive layout |
| advertisement | Marketing material, large graphics, irregular layout | The irrelevant upload a real intake queue must reject |

## Leakage risk and the response

The archive contains multiple pages from the same physical document.
Every manifest row carries a `doc_group_id`; splits are assigned over
groups, never over pages, so no source document appears on both sides of
the divide. Verified by `tests/test_leakage.py`, including a poisoned
fixture the check must reject.

## Ethics

The archive is public and contains no client information belonging to any
institution, which avoids the privacy risk that would attach to genuine
onboarding documents. Nevertheless: acknowledge the dataset authors and
the pretrained model sources; publish no page image that identifies a
private person; select example images for the report and slides that
carry no personal detail.

The dataset is a **proxy** for genuine onboarding material, not a sample
of it — no lawfully usable public collection of real onboarding documents
exists. This limits how far the results generalise to a live intake
queue, and the report states it in both §3 and the limitations section.

The intended use is triage with human oversight: the model flags
low-confidence pages for review rather than deciding unsupervised,
because a misrouted document delays a person's application.
